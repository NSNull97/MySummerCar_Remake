# Pause and settings menu styling — 2026-09-04

Status: implementation complete; final Unity regression/capture checks passed.
The user's visual approval remains pending.

The user accepted the real-car/home main menu and explicitly requested the same
style for Pause and Settings. This authorizes a presentation-only amendment to
the 08A lock: existing layouts, names, routes, values, transactions and input
bindings remain the compatibility baseline. The main-menu lamp/rear-fog request
is a separate final amendment documented in the main-menu report.

## Changes

`GameUiRoot.MainAndHud.BuildPauseRoute` reuses `MainMenuPanel` and five
`MainMenuButton` controls. The 400×640 panel, 332×66 buttons, positions, action
order and callbacks are retained. Resume gets actual route focus instead of a
permanent selection flag. Hover/press use unscaled time and the existing Reduced
Motion preference. The development-only reference placeholder is no longer
visible in Pause.

`UiFactory.MenuScreens.cs` supplies opt-in category/compact buttons, neutral
fields and dividers, and styling wrappers around the existing Slider/Toggle.
Dense controls omit external shadow/glow. `GameUiRoot.Settings.cs` uses these
widgets without changing its layout or editing logic. Apply/Reset/Cancel,
steppers, rebinding, capability states, pending/applied values and return routes
retain their existing implementations. No dropdown or new settings system is
introduced.

`GameUiRoot.BuildNotice` and `BuildConfirmationDialogRoute` use the same neutral
glass and button treatment, including destructive quit text. Their dimensions,
timers, callbacks and confirmation rules are unchanged; the confirmation's
technical reference placeholder is removed.

`MainMenuStyle` values are shared by explicit opt-in widgets. Existing factory
defaults and HUD rendering are unchanged. The only extension of
`AddMainMenuVisuals` is an optional `includeShadow=true` argument, preserving the
main menu's established behavior. The existing `UiGlassKind.MainMenuNeutral`
already selects the correct cached menu texture or `PauseFrozen` capture.
There is no additional capture camera, per-control blur or per-frame capture.

## Compatibility and verification

No save DTO, schema, public route ID, gameplay camera, world coordinate or input
binding changes. No asset migration or manual rewiring is required. Newly
authored source files include their Unity `.meta` files.

The first combined verification completed in Unity 6000.3.11f1: 45/45 EditMode
and 39/39 PlayMode, both with zero failed/skipped/inconclusive. Results are
`Artifacts/MainMenuRedesign/tests-home-atmosphere-style-edit-20260904-01.xml`
and `tests-home-atmosphere-style-play-20260904-01.xml`. This includes existing
layout/transaction/rebind tests, paused mouse hover and keyboard submit at
`Time.timeScale=0`, return focus, actual captured/frozen blur and unchanged frozen
pixels after the source camera changes. Native 1920×1080 captures under
`Captures/SettingsPause/` show Graphics, General, Pause and Settings from Pause;
they were visually checked for readable text, clipping and glass rendering.
They are isolated fixtures with actual HDRP camera output, not a player's save.
The rejected first fog comparison is unrelated to these UI styling results;
see the main-menu report for its correction and the later system-time work.

The prior accepted main-menu results (38 PlayMode checks and their spawn/orbit
captures) precede this change and do not validate these new screens.

Final system-time integration repeated the entire suite successfully:
`tests-home-system-time-edit-20260904-02.xml` 54/54 and
`tests-home-system-time-play-20260904-02.xml` 40/40, with zero failed/skipped.
The four settings/pause native images were regenerated by that final pass.
Only user review remains; open `Assets/Game/Bootstrap/Bootstrap.unity`, enter
Play and use Settings, or enter a game and press Esc for Pause.
