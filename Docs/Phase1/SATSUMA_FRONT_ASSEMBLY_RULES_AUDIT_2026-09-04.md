## 1. Установка: точные условия оригинала

Обозначения: `I` = `Data.Installed`, `B` = отдельный защёлкивающийся `Data.Bolted`, а не «все болты затянуты до конца». В парных строках порядок ID — FL / FR.

|---|---|---|---|---|

| Поворотные кулаки / spindle | 111700 / 110678 | `Wishbone.I`, затем `Wishbone.B` | `Drop part` → соответствующему рычагу GO32023 / 34825 `Removal.Detach=true` | I+B уже есть; вместо события при неудачной попытке выдаётся отказ |
| Передние стойки | 107329 / 108451 | `Spindle.I`, затем `Spindle.B` | `Drop part` → spindle GO21615 / 22276 | I+B уже есть; событие отсутствует |

| Тормозные диски | 105128 / 108653 | `Spindle.I`; `Already installed` исключает уже установленный диск; затем `Spindle.B` | `Drop part` → spindle | Есть I spindle и **лишнее I стойки**; B spindle нет |
| Полуоси | 108507 / 110985 | `Discbrake.I` и **`!Discbrake.B`**, затем `Already installed` | При затянутой гайке диска просто возврат к ожиданию, не `Drop part` | У обоих corner mounts отсутствуют даже `RequiredOccupiedMountIds`; I и обратное B не перенесены |

Критические доказательства: в обычном `Check bolts` идут `GetFsmBool(Data, Bolted)` и `BoolTest`: `isTrue=ASSEMBLE`, `isFalse=DISASSEMBLE`; переход `DISASSEMBLE -> Drop part`, действие `SetFsmBool(Removal, Detach, true)` адресует **основание**, не удерживаемую новую деталь. В `Brake bolted` полуоси направления обратные: `isTrue=LOOP`, `isFalse=ASSEMBLE`. Эта инверсия подтверждена обеими сторонами непосредственно по срезам параметров, а не названием состояния.

У рулевой колонки Assembly109461 есть `Check bolts` рейки с тем же `Drop part` на GO32711, но нет самостоятельного `Requirements`-чтения `Installed`: это отдельная вариация цепочки, не повод распространять одну схему на все детали. Наш explicit dependency требует I рейки, но не B.

Важно: показ превью при I основания и последующая неудачная попытка срыва при !B — не эквивалент превентивному скрытию точки или общему запрету. Установка тяги до spindle разрешена исходным FSM; последующее соединение тяги со стойкой — отдельная уже исследованная механика.

## 2. Пороги крепежа

Порог берётся из таблицы FSM-переменных, **не из сохранённого числового payload аргумента с `useVariable=1`**. Например, подрамник содержит старые inline 24/12, но реально использует `BoltedYES=26`, `BoltedNO=0`.

| Группа | BoltCheck FSM, FL / FR | Сумма всех стадий | Оригинал ON / OFF | Текущий generated mount ON / OFF |
|---|---|---:|---:|---:|
| Подрамник | 107345 | 32 | 26 / 0 | **1 / 0** |
| Рычаг | 113307 / 114055 | 16 | 2 / 0 | 2 / 0 |
| Spindle | 110196 / 110399 | 8 | 2 / 0 | 2 / 0 |
| Стойка stock | 108085 / 108452 | 56 | 3 / 0 | **1 / 0** |
| Рейка | 113483 | 32 | 24 / 0 | **1 / 0** |
| Колонка | 108776 | 16 | 10 / 0 | **1 / 0** |
| Тяга | 111004 / 104921 | 8 | 8 / 0 | 8 / 0 |
| Диск | 104208 / 107488 | 8 | 2 / 0 | **1 / 0** |
| Полуось | 107527 / 110145 | 24 | 2 / 0 | **1 / 0** |
| Колесо, пример steel1 | Use113900, не отдельный BoltCheck | 32 | 1 / 0 | 1 / 0 |

Причина несовпадений: `ConfigureFastenerGroups` сначала создаёт всем `FastenerGroupDefinition.CreateCompatibility` (ON=1), а точечные overrides для этих шести групп отсутствуют. Это не проблема вида меша гайки/болта. Метаданные и размеры крепежа не заменяют правильную групповую семантику.

Латч оригинала: из OFF переход в ON при сумме >= YES, обратно при сумме <= NO. Промежуточное ослабление не сбрасывает B немедленно. Уже принятое сохранение нашего latched B отдельно от суммы и физические позы не меняются этим аудитом.

## 3. Снятие рукой: это отдельная таблица правил

В исходных Removal FSM `Mouse off` проверяет `Detach` каждый кадр: true сразу переводит в `Remove part`, **в обход пользовательских `Requirements`**. Обычный ПКМ доступен через `Requirements`, где `BoolNoneTrue -> REMOVE`, `BoolAnyTrue -> LOOP/Wait`. Поэтому аварийное событие от сборки нельзя подменять обычным `CanRemove`.

| Снимаемая деталь | Removal FSM, FL / FR | Условия обычного снятия оригинала |
|---|---|---|
| Подрамник | 107346 | Свой !B; не установлены рейка, оба рычага и блок двигателя (DB GO35519) |
| Рычаг | 113308 / 114056 | Свой !B и не установлен соответствующий spindle |
| Spindle | 110197 / 110400 | Свой !B и не установлена соответствующая stock-стойка |
| Стойка stock | 108086 / 108453 | Свой !B и **тяга не установлена**; проверяется I тяги, не её B |
| Тяга | 111005 / 104922 | Свой !B; два дополнительные `db_RemoveReq` равны null и ничего не добавляют в этом frozen FSM |
| Диск | 104209 / 107489 | Свой !B и активен соответствующий wheel-install trigger, то есть колесо не занимает узел; `IsActive.isNotActiveEvent=LOOP` |
| Полуось | 107526 / 110144 | Свой !B **и !B диска**; установленный, но незатянутый диск сам по себе не запрещает снятие |
| Колесо steel1 | 113901, `Requirements 2` | `SetGrip.OnGroundDown=false` и `Use.Tightness<=0`; true у OnGroundDown немедленно даёт LOOP |

У рейки Removal113484 обнаружена особенность самого донора: два активных `GetFsmBool` читают I левой/правой тяг, но **оба пишут Required1**, затем собственный B пишется в Required2. Следовательно, при обычном последовательном выполнении правое значение перезаписывает левое. Это не доказательство намерения автора разрешать удаление рейки под левой тягой; нужна отдельная проверка оригинала перед буквальным переносом этого бага. Проверки колонки среди этих трёх чтений нет, тогда как у нас `RemovalBlocked(steering-rack, steering-column)` задан вручную.

На момент этого read-only аудита не были перенесены: блокировка снятия стойки
установленной тягой, снятия полуоси затянутым диском и ground-gate колеса.
Впоследствии первые две вошли в точечный пакет C; там же добавлены явные
исключения ложного обратного запрета диск←полуось и spindle←диск. Подробный
актуальный контракт и статус тестов:
[пакет C](SATSUMA_MANUAL_REMOVAL_RULES_FIX_2026-09-04.md). Ground-gate остаётся
открытым. `requiredBoltedMountIds` ради этих manual-проверок не использован:
этот массив задаёт structural/install семантику, а не обычное снятие.

`BuildVerifiedAssemblyDependencies` эвристически переводит `Required/Required1` в `InstallRequiresInstalled` + обратный `RemovalBlockedWhileInstalled`, а `DetachPart` — снова в `RemovalBlockedWhileInstalled`. **Имя переменной, адресующей действие, принято за декларацию запрета.** Для части пар результат случайно совпадает с отдельно прописанным Removal (рычаг↔spindle), но это не подтверждает правильность преобразования в общем случае. Для передка явные I/B правила заданы вручную, а interchangeable диски/полуоси обходят part-level генерацию и требуют corner-level правил.

## 4. Срыв при езде: текущая реализация покрывает только колёса

Для рычагов, spindle, стоек и полуосей проверенные FSM проходят `Bolts OFF -> Bolts ON -> Check break`. В `Check break`: при Tightness<=0 возврат OFF; при скорости **строго больше** порога — `Chance`. `Chance` вычисляет `w=(C-Tightness)/100` и передаёт в `SendRandomEvent` события BREAK с весом w и FINISHED с весом 1. При FINISHED `Wait` = **1 секунда realTime**, затем новая проверка. Эти сырые веса подтверждены. Формула вероятности `w/(1+w)` для положительного w соответствует **текущей нормализации у нас**, но в данном аудите не доказана по внутреннему donor helper; его реализация и поведение при нулевом/отрицательном w остаются pending.

| Группа | Проверенные FSM | Порог скорости | C в формуле | Сейчас |
|---|---|---:|---:|---|
| Рычаги | 113307 / 114055 | >50 км/ч | 15 | speedRetentionPolicy=None |
| Spindle | 110196 / 110399 | >50 км/ч | 7 | None |
| Стойки stock | 108085 / 108452 | >50 км/ч | 55 | None |
| Полуоси | 107527 / 110145 | >10 км/ч | 23 | None |
| Колёса, steel1 Use | 113900 | Полностью свободное: >5 км/ч, сразу BREAK; частично: >33 км/ч | 32 | Формула/пороги есть, **интервал неверный** |

Контрольные байты первых float аргументов C: рычаг `00007041`=15, spindle `0000e040`=7, стойка `00005c42`=55, полуось `0000b841`=23. Скорость в Check break: `00004842`=50, для полуоси `00002041`=10. Оба оператора активны, operation1=вычитание, operation3=деление; `Wait` содержит 1.0 и `realTime=true`. Прочитан read-only `SendRandomEvent.cs`: он вызывает `ActionHelpers.GetRandomWeightedIndex(weights)`. Сам `ActionHelpers.GetRandomWeightedIndex` не найден по проверенному пути и не прочитан; точная нормализация и обработка отрицательных весов донора этим источником не подтверждены.

У нас `EvaluateFastenerRetentionPolicies` вызывается из каждого FixedUpdate и каждый раз делает новый random sample. Даже при правильной разовой вероятности это существенно завышает частоту срыва колёс по сравнению с donor Wait1s. Для остальных перечисленных групп политики вообще не назначены. Подрамник, рейка, тяги и диски в проверенных BoltCheck не имеют этой скоростной ветки: **нельзя раздать wheel-policy всему передку**.

В `Break off` оригинал сбрасывает стадии и Tightness, снимает B, затем в `Remove other` адресно выставляет `Removal.Detach`. Для wishbone113307 подтверждены owner/self, диск GO347, spindle GO21615 и установленный wheel-child из двух альтернативных pivot GO30664 / GO21889. Для полуоси107527 — owner/self. Для spindle110196 и strut108085 также есть адресные SetFsmBool/GetChild; это не универсальное правило «удалить всех потомков». Полный список побочных адресатов и поведение отсутствующих wheel-child нужно валидировать отдельным bounded fixture до реализации этих двух каскадов; геометрию это не требует менять.

Предупреждение об аудите CSV: `Phase1SatsumaV1dBoltCheckAudit.csv` для этих front FSM пишет `ReferencesSpeedKMH=false` и `ChanceMaximumTightness=32`, хотя raw action bytes явно показывают другое. Эти эвристические поля **не являются достаточным основанием для конфигурации**. Также наличие BREAK не означает «нулевая затяжка обязана немедленно разрушить неподвижную машину»: для перечисленных front BoltCheck скоростная ветка находится после ON, а отдельный срыв основания вызывается неудачной сборкой. Иные collision/damage FSM этим выводом не исключаются и здесь не обследовались.

## 5. Минимальный порядок следующего исправления

1. **Данные установки и пороги.** Явные project-owned corner rules из разделов 1–2; убрать неподтверждённые I spindle для тяг и I стойки для дисков, добавить полуось I диска + !B. Разделить проверку доступности точки, результат попытки установки и событие срыва основания. Не генерировать runtime из FSM и не превращать install B в постоянное structural B. Tests: обе стороны, I/!I, B/!B, все пороги−1/порог, без изменения принятой физики.
2. **Обычное снятие против принудительного срыва.** Перенести отдельно подтверждённые Removal-условия, не выводить их обратным обходом installation graph. Тесты: тяга блокирует снятие стойки даже при своей B=false; диск B блокирует полуось; аварийный Detach не вызывает обычный CanRemove. Donor-особенность рейки и точное происхождение `OnGroundDown` оставить явно pending до локального подтверждения, не выдумывать исправление.
3. **Скоростной BREAK.** Отдельные данные C/скорость/интервал/адресаты для передних групп; wheel Wait1s исправлять с тестом времени, не трогая вылет, вращение или опорные силы. До переноса каскадов уточнить небольшой список адресатов; не запускать универсальное «всё незатянутое развалить».

Ключевые места текущего кода: `Phase1SatsumaBaselineBuilder.cs:4087` (compatibility ON1), `:6275` (mount sequence), `:6656` (explicit/эвристические dependencies); `AssemblyDefinitions.cs:154` (CreateCompatibility), `:194` (wheel chance); `AssemblyGraph.cs` (раздельные install/structural/removal проверки); `VehicleAssemblyController.cs:485` (покадровая retention policy), `:945` (обычное снятие), `:981` (forced break).

Итог: ошибки находятся в **семантике авторинга правил**, пропущенных порогах и временной политике BREAK. Исправлять принятую кинематику для их устранения оснований нет. В этом проходе изменён только данный отчёт; donor, Assets и Unity не изменялись.
