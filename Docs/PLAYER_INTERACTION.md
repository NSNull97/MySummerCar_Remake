# Player and Interaction

## First milestone scope

- first-person look;
- walking and crouching;
- configurable interaction range;
- pickup and carry;
- place and drop;
- simple object rotation;
- contextual interaction;
- tool activation;
- clear debug visualization.

## Interaction boundary

Player input produces an intent. Interaction services identify candidates and call an explicit capability on the target.

Avoid object-name checks and one mega-script that knows every item type.

Possible capabilities:

- `IPickupTarget`
- `IPlaceable`
- `IInteractable`
- `IToolTarget`
- `IMountablePart`
- `IFastenerTarget`

Do not add interfaces until at least one concrete use exists.

## Carrying

Carried objects should support:

- stable identity;
- controlled physical following;
- collision behavior;
- mass-aware tuning;
- dropping and throwing;
- prevention of impossible tunneling;
- save compatibility.

Avoid parenting a live Rigidbody to the camera without a deliberate physics strategy.

## Camera and body

Start with a reliable camera/controller. Full-body presentation and procedural hands come later.

Future IK targets:

- steering wheel;
- gear lever;
- ignition;
- tools;
- fasteners;
- held objects.

Core interaction state must not depend on an animation completing perfectly.

## Validation

Test:

- pickup/drop round trip;
- loss of target;
- target destruction/unload;
- heavy/light objects;
- save while carrying;
- mounting from hand;
- cancellation;
- collisions near walls and floor.

## Milestone 4 implementation

Milestone 4 owns a small playable physical-interaction slice under:

- `Assets/Game/Interaction/Runtime` — capabilities, target host, raycast candidate query, physical carrying and carried-object snapshot;
- `Assets/Game/Player/Runtime` — movement, look, Input System routing, intent orchestration and debug overlay;
- `Assets/Game/Player/Content/Input/M4_Player.inputactions` — keyboard/mouse and gamepad actions;
- `Assets/Game/Player/Content/Scenes/PlayerInteractionPrototype.unity` — isolated validation scene generated by the M4 Editor builder.

### Runtime flow

```text
InputActionAsset
  -> PlayerInputRouter (intent only)
  -> FirstPersonMotor / FirstPersonLook
  -> PlayerInteractionController
  -> RaycastInteractionCandidateSource
  -> InteractionTargetHost
  -> explicit capability
```

`InteractionTargetHost` is an explicit registry of `MonoBehaviour` capability implementations. The query never dispatches by object name. A collider without a host is an invalid/occluding target; a destroyed or unloaded host invalidates the cached candidate. The currently carried Rigidbody is the only explicit query exclusion, allowing a mount behind the held item to remain selectable without making walls or unrelated props transparent.

Implemented capabilities have concrete uses:

- `IPickupTarget` — `PhysicsPickupTarget`;
- `IContextInteractionTarget` — `ContextToggleTarget` prototype;
- `IToolActivationTarget` — `ToolActivationCounterTarget` prototype;
- `IMountHandoffTarget` — `PrototypeMountHandoffTarget`, only as a future vehicle-assembly handoff boundary.

### Physical carrying

`PhysicalCarryController` does not parent the held `Rigidbody` to the camera. It disables gravity temporarily, switches to continuous collision detection, ignores only player/held colliders and drives linear/angular velocity toward a carry anchor in `FixedUpdate`. Excess separation releases the object. Original Rigidbody gravity, interpolation, damping and collision mode are restored on drop/place/throw/handoff and also through idempotent cleanup when the controller is disabled or destroyed during scene/player lifecycle changes.

Placement uses a surface ray plus overlap rejection. Throwing restores normal physics before applying an impulse. Rotation changes the carry target orientation; it does not directly teleport the visual mesh.

Disabling `PlayerInputRouter` clears movement and crouch intent. Mouse look/held rotation consume pointer delta in degrees per pixel; gamepad stick input is a rate in degrees per second multiplied by unscaled delta time.

### Controls

| Intent | Keyboard/mouse | Gamepad |
|---|---|---|
| Move / look | `WASD` / mouse | left / right stick |
| Crouch | hold `Left Ctrl` | hold right-stick press |
| Interact, pickup, mount handoff | `E` | west button |
| Drop | `G` | east button |
| Place | `F` | south button |
| Throw | left mouse | right trigger |
| Rotate held object | hold right mouse + mouse | hold left trigger + right stick |
| Tool activation | `R` | north button |

### Deliberate boundaries

- No full-body rig, hands or IK.
- No inventory slots or item stacking.
- No mount compatibility graph, fasteners or vehicle assembly state.
- No save storage or stable-ID resolver. Interaction only captures its domain snapshot.
- No donor input/FSM code or configuration was transferred.
