# Save Master: аудит схем сохранения

Проверено по исходному коду ремейка 6 сентября 2026 года. Программа редактирует
собственный native JSON-формат ремейка. Формат оригинального My Summer Car и
функции MSC Editor не используются как источник структуры сохранения.

последовательность восстановления задают существующие участники в
`Assets/Game/Save/Integration/`. Версии контейнера документа и версии отдельных
разделов независимы. Неизвестные разделы и версии сохраняются без изменения и
доступны для просмотра. Редактор не выполняет игровые миграции.

## Документ 18 и купленные детали

Save Master 1.0.2 поддерживает документы 16, 17 и 18. Игровая миграция
`SatsumaDynamicAssemblySaveMigration` повышает версию контейнера 17 → 18,
а новый `VehicleAssemblySaveData` использует внутреннюю схему 3. Envelope
`vehicle.satsuma` остаётся схемой 1; его версия не определяет версию сборки.

Схема 3 хранит купленные свечи, ремень генератора, масляный фильтр и лампы в
`dynamicParts`. Проверки используют существующие `VehicleItemPartCatalog` и
`VehicleItemSaveRestorePlanFactory` как источник соответствий: тип предмета ↔
тип детали, уникальный стабильный ID, состояние установки, место установки,
положение/поворот, скорости и сон физики. Обычные и купленные детали участвуют
в общей проверке занятости мест и затяжки. Индивидуальные и массовые действия
с крепежом поддерживают схемы 2 и 3.

Между `items.instances`, `vehicle.satsuma` и `world.entities` проверяется один
владелец физического состояния: динамическая деталь должна иметь живую запись
предмета соответствующего типа, не быть каноническим размещением и не иметь
второй записи физики мира. Для текущих сборок нельзя терять динамическое
описание купленного сборочного предмета. Редактор не создаёт такие записи и
не выполняет их игровую миграцию; существующие версии, ID, состав коллекций
и неизвестные поля сохраняются. Документы 19+ остаются только для чтения.

## Актуальные настройки Satsuma — 1.1.0

Дополнительные состояния текущего ремейка не меняют document 18, envelope 1
или assembly 3. Источники: `VehicleAssemblySaveData`, `AssemblyMechanicalConditionState`,
`AssemblyValveAdjustmentState`, `AssemblyServiceCapState`, `VehicleSimulationContracts`,
`SatsumaOperatingState`, `Phase1SatsumaOperatingAuthoring`, а также действующие
`SATSUMA_ENGINE_PLAYER_GUIDE_RU_2026-09-06.md` и документы operating model в `Docs/Phase1`.
Имена конкретных файлов можно найти поиском по типам в `Assets/Game`.

- Активный `mechanicalCondition` (schema 1) разрешён девяти штатным владельцам:
  piston1–4, crankshaft, head-gasket, water-pump, alternator, rocker-shaft.
  `conditionPercent` 0–100; 0 требует `broken=true`.
- `valveAdjustment` (schema 1) принадлежит rocker-shaft: intake x/y/z/w 4–10,
  exhaust x/y/z/w 3–9. Это условные значения; 7/6 — текущие исходные ориентиры.
- `serviceCaps` (schema 1): rocker-cover/gt-rocker-cover-gt [0], radiator [1],
  brake-master-cylinder [2,3], clutch-master-cylinder [4]. Количество и порядок
  kinds защищены; углы 1–359°. 359 означает закрытую крышку.
- `satsumaOperatingState` (schema 1): brakeFront/RearLiters 0–1, clutchLiters
  0–0.5, oilContaminationPercent 0–100, oilPressureBar 0–10,
  coolantPressurePsi 0–50, crankingSeconds 0–60, radiatorFanRunning boolean.
  Панель разрешает менять жидкости и загрязнение; давления/вентилятор/прокрутка
  остаются показаниями симуляции.
- Presence flags неизменяемы. Inline default DTO с отсутствующим/false флагом
  не активируется и не редактируется. Неизвестная версия активного DTO переводит
  раздел в просмотр; неизвестная версия неактивного default DTO этому не мешает.
- Купленные расходники сопоставляются по стабильному ID с `items.instances`:
  их `condition/isBroken` остаются состоянием предмета. Новые механические
  extensions не добавляются в dynamicParts.

`VehicleTuningCatalog.Build` только описывает существующие активные поля.
`SaveSession.ApplyVehicleTuning` проверяет разрешённый набор, конечные числа,
диапазоны, структуру и все домены на клонах до единой записи в историю.
Напряжение обновляет batteryCharge01=clamp(voltage/12.6,0,1); нулевой
mechanical condition устанавливает broken=true после обработки всего набора.
Положительное состояние само по себе не сбрасывает поломку. Неизвестное,
неактивное или вычисляемое поле этим API изменить нельзя.

Ориентиры oil=3 L/coolant=5.4 L не становятся новыми максимумами старых DTO.
Схождение и метка свободной детали отображаются без изменения: runtime
рандомизирует их при восстановлении. Никакого заявления о гарантированном
запуске двигателя или выполненной проверке ездой панель не делает.

## Что проверяется

- Типы, целочисленные поля, конечность чисел и предел игровых float; ненулевые
  кватернионы, допустимые скорости физики, диапазоны камеры и потребностей.
- Соответствие стабильных идентичностей и структуры исходному файлу проверяет
  `SaveSession`; пользователь не может переименовать или создать сущности.
- Для машин: соответствие part↔mount, уникальность записей, lifecycle,
  совместимость детали с известным mount, наличие установленной детали под
  вставленным болтом, inserted/seated/stage, точный maximumStage, состав и
  защёлка групп крепежа. `IsBolted` имеет гистерезис и не эквивалентен простой
  проверке «все болты затянуты».
- Схождение −6…6°, метка распредвала 0…360°, регулировки генератора 0…8,
  распределителя 0…20, смеси 10…22, масляного фильтра 0…8 целыми ступенями.
  Настройка привязана к типу детали; снятый фильтр имеет нулевую затяжку.
  Наживление двигателя допускает только один pending-болт свободного блока.
- Проводка, зависимости кабелей и клемм, дворники, ручник, перечисления
  двигателя, неотрицательные жидкости и заряд аккумулятора.
- Для предметов: максимальное содержимое, состояние 0…100, варианты,
  согласованность жидкости с её ID, количество дочерних предметов контейнера,
  диапазоны известных scalarStates, дубли идентичностей содержимого.
- Для денег: signed Int64 без округления через double, последовательность
  операций, debit/credit, положительные суммы, before/after и хвост=баланс.
- Для времени: допустимая дата, целые микросекундные тики, остаток [0,1),
  скорость (0,1000]. Переход сравнивается с исходным календарным началом мира,
  чтобы отдельное изменение даты не рассогласовало elapsedGameTicks.

## Безопасные действия

`SchemaActions` возвращает проверенную копию данных; запись на диск, отмена,
просмотр изменений и резервирование принадлежат `SaveSession`.

- `SetFasteners`: затянуть/ослабить уже вставленные крепежи установленной
  машины; отсутствующие болты и детали не создаются. Группы пересчитываются по
  точным порогам. Неизвестные определения или неполная группа отменяют действие.
- `SetFastenerStage`: изменить один существующий вставленный крепёж и
  согласованно обновить его группу.
- `SetWiring`: выбрать постоянные провода текущей схемы 2, убрать затяжку клемм
  без кабелей, при явном запросе затянуть подключённые клеммы.
- `ResetNeeds`: обнулить потребности и накопленные эффекты, сохранив вес.
- `SetBalance`: добавить новую операцию `Adjustment` от `tool.save-master`,
  обновить баланс и номер следующей операции. Старый журнал остаётся целым.
  Прямое дописывание операций через произвольный JSON запрещено ядром.
- `SetTime`: согласованно поменять дату/время, elapsedGameTicks и dayIndex,
  сохранив начало игрового мира. Дата до начала прохождения запрещена.

## Проводка действительно сохраняется

`VehiclePersistenceBindingCore.TryCapture` вызывает
`SatsumaElectricalSystem.CaptureSaveData`; `ApplyValidated` вызывает
`SatsumaElectricalSystem.TryRestore`. Это часть существующего save pipeline,
а не новый временный флаг интерфейса.

В `vehicles[].electrical` текущая схема 2 хранит 26 стабильных имён в
`installedConnectionIds`. Это постоянные соединения, а не идентичность
сущностей, поэтому у этого массива есть узкое исключение из защиты состава.
`batteryPlusStage`, `batteryMinusStage`, `starterCableStage` допускают 0…8.
Для плюса требуется `BatteryHarness` либо `Starter`, для минуса —
`GroundBattery`, для крепежа стартера — `Starter`. Старые boolean-поля схемы 1
остаются для миграции в игре; редактор не выдаёт их за полный текущий жгут.

## Каталоги и происхождение

`Core/SchemaVehicleDefinitions.cs` содержит только скалярные метаданные 334
проектных FastenerDefinition и 149 MountPointDefinition. Источники:

- `Assets/Game/Vehicle/Content/**/Definitions/` — существующие M05/M06;
- `Assets/Game/LegacyImport/RuntimeBaseline/Vehicles/Satsuma/FastenerDefinitions/`;
- `Assets/Game/LegacyImport/RuntimeBaseline/Vehicles/Satsuma/MountDefinitions/`.

Это project-owned определения сборки. Снимок сохраняет ID, размеры, пределы,
связи, пороги и SHA-256 исходных `.asset`, без Unity YAML, геометрии, текстур,
аудио, донорных MonoBehaviour или других бинарных payload. Когда в старом
определении отсутствует группа, применяется существующее правило
`FastenerGroupDefinition.CreateCompatibility`: сумма MaximumStage только
RequiredForRemoval, пороги on=1/off=0, либо пустая группа.

`Core/SchemaItemDefinitions.cs` содержит пределы 152 типов предметов из
проектного `Assets/Game/Items/Content/Definitions/Phase1ItemDefinitionCatalog.asset`
и SHA-256 источника. Встроенные снимки обеспечивают работу переносимой программы
без Unity и без доступа к установке оригинальной игры. После изменений
каталогов ремейка снимки нужно обновить и повторить регрессионные проверки.

Воспроизведение без Unity, из корня репозитория (PowerShell 7):

```powershell
./Tools/SaveMaster/Update-SchemaCatalogs.ps1
./Tools/SaveMaster/Update-SchemaCatalogs.ps1 -Check
dotnet build Tools/SaveMaster/Core/SaveMaster.Core.csproj
```

Генератор читает только перечисленные проектные каталоги: определения
FastenerDefinition/MountPointDefinition распознаются по проектному
`m_EditorClassIdentifier`; GUID ссылок крепежа разрешаются через их `.meta`.
Отсутствующая ссылка, повтор ID, неверный максимум или чужой крепёж группы
прерывают генерацию. ID записей и диапазонов сортируются, свойства JSON имеют
фиксированный порядок, пути относительные. `-Check` повторно вычисляет все
хэши и скалярные данные и требует точного совпадения встроенных снимков, не
записывая файлы. Эта операция повторно использует существующие нормализованные
проектные настройки и не переносит новые данные из оригинальной игры.

## Границы проверки

Редактор показывает все существующие поля поддержанных разделов, но не
эмулирует игру. Не реализованы полная проверка всех каталогов NPC/услуг/погоды,
взаимодействий квестов, пространственных столкновений, соответствия loaded
scene-объектам, доступности сцен и полная миграция старых графов сборки.
Новые подсистемы, которых ещё нет в native DTO, не выдумываются.

Монтаж и демонтаж деталей, создание предметов и изменение постоянных ID
не представлены как безопасные действия. Существующие ссылки сохраняются.
Физически допустимая координата может находиться под землёй или внутри стены;
JSON-проверка не знает геометрии мира. После значительных изменений нужен
контрольный запуск копии слота в игре. Прохождение сюжетного сценария не
проверяется одним фактом успешного декодирования файла.

Изменений runtime, stable ID, save DTO, UI 08A и игровых миграций эта программа
не требует. Формат остаётся совместим с существующим native save pipeline.
